# 本地分支合并编排与版本发布规划

以本地导入的提交、分支与标签数据为输入，计算：

- 分叉分支的**合并/变基执行顺序**；
- **下一语义化版本号**与**变更日志**；
- 所有结论在不同操作顺序下保持一致，并输出可解释的判定依据（`rationale`）。

## 模块结构

| 模块 | 职责 |
| --- | --- |
| `release_planner/models.py` | 数据模型：`Commit` / `Tag` / `SemVer` / `MergePlan` |
| `release_planner/graph.py` | 提交图导入、校验（缺失父提交、循环父边、重复提交）与拓扑查询 |
| `release_planner/planner.py` | 合并顺序、下一版本号、变更日志与判定依据 |
| `release_planner/store.py` | 线程安全存储、历史快照回溯、旧格式兼容导入 |
| `main.py` | FastAPI HTTP 接口 |

## 提交图导入与校验规则

- 提交按 `id` 唯一存储。导入内容完全相同的提交为**幂等操作**（返回 `added=0`）；
  `id` 相同但内容不同判定为冲突，拒绝并返回 `duplicate_commit`，不静默覆盖。
- 规划前执行校验，任一非法输入立即拒绝，不跳过、不截断：
  - `missing_parent`：某提交声明的父提交不在图中；
  - `cyclic_parent_edge`：父边构成环（错误信息给出环路径）。
- 合并提交（多个父提交）天然由拓扑排序支持。

## 合并顺序判定规则

1. 对各分支头可达提交取并集，减去所有**标签提交的祖先集合**（已发布部分），
   得到待发布提交集合。
2. 在待发布子图上做拓扑排序：**父提交必先于子提交，合并提交必须在两个父提交之后**。
3. 同一时刻存在多个可输出提交时，按提交 `id` 字典序出队（小顶堆）。
   因此无论分支按什么顺序传入、提交按什么顺序导入，输出顺序唯一确定。
4. 分叉点（最佳公共祖先）写入 `rationale`，便于解释合并来源；多个并列分叉点
   按 id 字典序取最小者，同样保证确定性。

## 版本计算规则

版本遵循 SemVer 2.0.0：`MAJOR.MINOR.PATCH[-prerelease][+build]`。

1. **基线版本**：将所有标签按 semver 规则排序后取最高者；无标签时基线为 `0.0.0`。
   - 比较顺序：核心号 → 预发布段；有预发布段者**低于**同核心号正式版；
     预发布段逐段比较，纯数字段按数值、字母段按字典序，数字段低于字母段，
     公共前缀相同时段数多者更高（`rc` 系列标准顺序）。
   - **构建元数据（`+build`）不参与排序**，仅保留在输出中。
2. **待发布变更级别**：取待发布提交 `change` 字段的最高级别
   （`major > minor > patch > none`）。
3. **下一版本**：
   - 无待发布提交：保持基线不变；
   - 基线是**预发布版本**（如 `1.0.0-rc.1`）：该核心版本尚未正式发布，
     待发布变更并入这一未完成的发布，下一版本**毕业为正式版**（`1.0.0`），
     并丢弃构建元数据；
   - 基线是正式版本：按最高级别提升一次
     （major 进位后清零、minor 进位后 patch 清零），并清除预发布/构建元数据。
4. **幂等**：重复导入同一提交不会在图中产生第二条记录，因此既不会重复计入
   变更日志，也不会重复提升版本号。

## 并发与幂等语义

- `RepoStore` 内部使用互斥锁保护所有读写；批量导入在同一把锁内完成，
  并发导入不会丢失变更，也不会重复应用（按提交 id 幂等去重）。
- 每次成功的写批次生成一个**不可变深拷贝快照**。`checkout(version)`
  可回溯到任一历史状态，之后的规划结论与当时完全一致、可复现。
- `import_records()` 兼容旧格式字典记录，字段缺失时使用稳定缺省值：
  `parents=()`、`message=""`、`branch=""`、`change="patch"`。

## 失败原因一览

| reason | 触发条件 |
| --- | --- |
| `duplicate_commit` | 同一 id 以不同内容重复定义 |
| `missing_parent` | 父提交缺失 |
| `cyclic_parent_edge` | 父边成环 |
| `unknown_branch` | 分支头提交不存在 |
| `unknown_tag` | 标签指向的提交不存在 |
| `invalid_version` | 版本号无法解析 / 历史版本号越界 |
| `empty_plan` | 未提供任何分支 |

## HTTP 接口

```text
POST /commits           批量导入提交（返回 added 数，幂等）
POST /tags              添加版本标签
POST /branches          设置分支头
GET  /plan              获取合并顺序、下一版本、变更日志与判定依据
POST /snapshots         显式生成快照，返回版本号
POST /checkout/{ver}    回溯到历史版本
```

错误响应形如：`409/404/422 {"detail": {"reason": "cyclic_parent_edge", "detail": "..."}}`。

## 本地验证方法

```bash
# 安装依赖（uv）
uv sync

# 运行全部单测（日志默认打印输入数据与判定依据，-s 可查看实时输出）
uv run pytest -s

# 启动服务
uv run python main.py
```

测试覆盖：分叉合并拓扑序、循环与缺失父提交拒绝、预发布排序与构建元数据、
重复导入幂等、分支输入顺序无关性、并发写入无丢失无重复、历史快照回溯可复现、
旧格式缺省字段兼容。
